# Промт для разработки этого приложения

Ниже — готовый промт, который можно дать другому ИИ (или разработчику), чтобы получить такое же
приложение. Второй, короткий, — для продолжения работы над уже существующим кодом.

---

## 1. Полный промт «сделай с нуля»

```text
Ты — senior .NET-разработчик и дизайнер интерфейсов. Сделай с нуля портативное приложение
Kanban для Windows 10/11 x64. Работай самостоятельно: создай проект, собери его, прогони тесты
и покажи результат. Не задавай уточняющих вопросов, если ответ можно выбрать разумно по умолчанию —
фиксируй решение в README.

ЦЕЛЬ
Один Kanban.exe рядом с базой kanban.db. Ничего не устанавливается, не пишется в реестр и %APPDATA%,
не требует прав администратора. Папку можно скопировать на флешку или другой ПК — доска переезжает
вместе с ней. Интерфейс открывается в браузере с локального адреса 127.0.0.1. Интернет не нужен,
кроме необязательной синхронизации.

ТЕХНОЛОГИИ
- .NET 8, self-contained, single-file, win-x64, WinExe (без консоли).
- ASP.NET Core minimal API, Kestrel, слушает только 127.0.0.1, порт из конфига (по умолчанию 5183,
  при занятости — следующий свободный).
- WinForms только для иконки в трее и уведомлений.
- SQLite через Microsoft.Data.Sqlite: journal_mode=DELETE, synchronous=FULL, Pooling=false,
  ForeignKeys=true, busy_timeout=5000.
- Фронтенд: vanilla HTML/CSS/JS без сборщиков и CDN. Все файлы (html/css/js/svg) вшиты в exe
  как EmbeddedResource и отдаются с Cache-Control: no-store.
- Никаких внешних пакетов, кроме Microsoft.Data.Sqlite.

ДАННЫЕ (SQLite, схема с миграциями через PRAGMA user_version)
Таблицы: boards, board_columns (WIP-лимит), cards (заголовок, описание, приоритет 0–3, срок, теги,
позиция, created_at, updated_at, archived_at), card_checklist (text, done, position),
attachments (kind = link|file, title, url, file_name, original_name, size).
Файлы вложений лежат в files\ с именем guid + расширение, лимит 25 МБ на файл.
Все даты — ISO-строки. Миграция старой схемы выполняется автоматически при запуске.

ФУНКЦИИ
1. Несколько досок, колонки, переименование двойным кликом, лимит WIP с подсветкой превышения.
2. Карточки: перетаскивание между колонками и внутри колонки, приоритет, срок (просрочено/скоро),
   теги, поиск по заголовку/описанию/тегам/пунктам чек-листа/вложениям.
3. Чек-лист: до 200 пунктов. На карточке на доске виден прогресс, прогресс-бар и первые 5 пунктов;
   отметка/снятие — кликом по пункту без открытия карточки; кнопка «ещё N» / «свернуть».
4. Вложения: ссылки (открываются в браузере) и файлы до 25 МБ (скачивание из карточки).
5. Архив: карточки скрываются с доски, но остаются в базе и экспорте; возврат и удаление из архива.
6. Экспорт: JSON (без бинарников), CSV для Excel (разделитель «;», CRLF, BOM), ZIP (data.json + files/).
   Импорт JSON и ZIP (формат по сигнатуре PK), перед импортом — резервная копия.
7. Резервные копии: при старте не чаще раза в сутки, вручную, хранить последние N (из конфига).
8. Обновление из папки updates\: version.json {version, file, notes}, замена exe через
   cmd-скрипт + Kanban.update.exe, автоматический перезапуск, очистка хвостов при старте.
9. Трей: открыть доску, синхронизировать, резервная копия, папка программы, проверка обновлений, выход.
10. Один экземпляр на папку (именованный мьютекс); повторный запуск открывает уже работающую доску.

СИНХРОНИЗАЦИЯ ЧЕРЕЗ WEBDAV (Яндекс.Диск, Mail.ru, Nextcloud, NAS)
- На сервере папка (по умолчанию Kanban): kanban.json + files/<guid>.<ext>.
- kanban.json — обёртка {format:"kanban-sync", formatVersion, revision, createdAt, appVersion,
  device, state:{boards, columns, cards}}. revision — случайный guid, создаётся при каждой отправке.
- Локально sync-state.json: localHash, remoteRevision, lastSyncAt, lastAction, lastMessage, conflict.
- Алгоритм: сравнить хеш локального состояния с lastHash и ревизию с сервера с lastRevision.
  Только локальные изменения → push; только серверные → pull (с резервной копией); оба → конфликт;
  ничего → «изменений нет». Первый запуск при непустом сервере — тоже конфликт.
- Вложения передаются по одному, только недостающие (имена файлов неизменяемы).
- Конфликт решается пользователем: «взять с сервера» (своя версия в backups\kanban-local-*.json),
  «загрузить своё», «позже». При push использовать If-Match, если сервер отдаёт ETag, но не
  полагаться на это: истина — в revision внутри файла.
- Пароль приложения хранить зашифрованным DPAPI (CurrentUser), в JSON без открытого текста;
  на другом ПК попросить ввести заново.
- Автоматически: при запуске (в фоне) и при выходе (с таймаутом), плюс кнопка и пункт меню.
- Для внешних адресов принудительно https; локальные (127.0.0.1, 10.*, 192.168.*, 172.16–31.*) — как есть.
- MKCOL: 405/403/409 на существующую папку не считать ошибкой — проверить через PROPFIND Depth: 0.
- Ошибки сервера переводить в понятный русский текст: 401/403 — «неверный логин или пароль
  приложения» (Mail.ru отвечает 403 и на обычный пароль вместо пароля для внешних приложений),
  507 — «закончилось место», таймаут — «сервер не ответил вовремя».

ИНТЕРФЕЙС
- Русский язык, тёмная и светлая темы (переключатель, выбор в localStorage), CSS-переменные.
- Шапка: логотип, вкладки досок, фильтры (приоритет/теги), поиск (Ctrl+K), архив, меню ⋯, тема.
- Доска: колонки с прокруткой, пустые состояния, подсветка цели при перетаскивании.
- Карточка: заголовок, 2 строки описания, чек-лист с галочками, чипы тегов/срока/приоритета,
  вложения; клик открывает диалог, Enter на карточке — тоже (но не на чекбоксе).
- Диалог карточки: поля, чек-лист (добавление, редактирование, удаление), вложения (ссылка/файл),
  «В архив», «Удалить», Ctrl+Enter — сохранить.
- Строка состояния: количество, резервная копия, папка, синхронизация (⇅), состояние сохранения.
- Баннеры: обновление и конфликт синхронизации с кнопками выбора версии.
- Диалог синхронизации: адрес, логин, пароль, папка, галочки «включить/при запуске/при выходе»,
  «Проверить подключение», «Синхронизировать», журнал результата, понятные подсказки.
- Эмодзи и иконки — только минимально; стиль сдержанный, скругления 8–12 px, без анимаций-«прыжков».

СБОРКА И ПОСТАВКА
- build.ps1 собирает ДВЕ самостоятельные папки: dist\Kanban (с синхронизацией) и
  dist\Kanban-Basic (без неё, -p:NoSync=true, Sync.cs исключён, в UI и трее нет синхронизации).
- Иконка assets\kanban.ico (16–256 px, тёмный скруглённый квадрат и три полосы: #4f8cff,
  #ffb020, #34d399) встраивается в exe и копируется рядом.
- Скрипт «Создать ярлык на рабочем столе.cmd» + shortcut.ps1 создают ярлык с иконкой.
- README.md для полной версии и README-basic.md для версии без синхронизации.
- Папки dist после сборки не должны содержать kanban.db, логов, конфигов и runtime.json.

КРИТЕРИИ ПРИЁМКИ
1. Запуск с флешки без установки; данные появляются только в папке приложения.
2. Создание/редактирование/перемещение карточек, чек-лист с отметкой на карточке, вложения,
   архив, фильтры, поиск — работают после перезапуска.
3. CSV открывается в Excel без «кракозябр»; ZIP-экспорт → импорт возвращает карточки и файлы.
4. Повторный запуск exe не создаёт второй экземпляр.
5. Обновление из updates\ заменяет exe и перезапускает приложение, не оставляя временных файлов.
6. Синхронизация: первый ПК отправляет, второй загружает, правки ездят в обе стороны, конфликт
   распознаётся и разрешается, при выходе изменения отправляются.
7. Версия без синхронизации: нет пунктов меню, кнопок и API /api/sync/*, всё остальное идентично.
8. Автотесты: smoke-тест API/переносимости/обновления и тест WebDAV на локальном сервере — зелёные.

ИЗВЕСТНЫЕ ГРАБЛИ (учти заранее)
- Minimal API теряет IResult у async-обработчика с единственным параметром HttpContext — писать ответ вручную.
- Статику отдавать с no-store, иначе после обновления exe браузер показывает старый JS.
- Pipeline публикации: перед сборкой останавливать запущенный Kanban.exe, иначе занят e_sqlite3.dll.
- SQLite нельзя синхронизировать файлом: только снимок через экспорт/JSON.
- При синхронизации нельзя генерировать новые имена файлов при импорте, иначе вложения
  перезаливаются каждый раз. Сохраняй имя, если оно безопасно.
- DPAPI-пароль не переносится на другой ПК — это нормально, нужно попросить ввести заново.
- Mail.ru: 403 вместо 401, нестандартный ETag и игнорирование If-Match, редирект http→https,
  возможен 403/409 на MKCOL существующей папки.
- У WinForms-потока есть SynchronizationContext: синхронизацию при выходе запускать через Task.Run,
  иначе взаимоблокировка.

ФОРМАТ ОТВЕТА
Сначала короткий план, затем реализация, затем отчёт: что сделано, как собрать, какие проверки
прогнаны и что осталось непроверенным (например, реальные Яндекс.Диск/Mail.ru без аккаунта).
```

## 2. Короткий промт «продолжи работу»

```text
Продолжи работу над портативным Kanban (E:\oclode\Kanban). Это .NET 8 WinExe + ASP.NET Core
minimal API + SQLite, интерфейс на vanilla JS вшит в exe. Две сборки: dist\Kanban (с WebDAV)
и dist\Kanban-Basic (без, -p:NoSync=true). Версия 1.2.2.

Структура: Program.cs (запуск, трей, обновление, синхронизация при старте/выходе), Api.cs
(эндпоинты, статика), Store.cs (SQLite, схема, импорт/экспорт), Infrastructure.cs (конфиг,
логирование, runtime.json), Updater.cs, Sync.cs (WebDAV-клиент и движок синхронизации),
wwwroot (index.html, style.css, app.js), assets (иконка, скрипт ярлыка), build.ps1,
README.md / README-basic.md.

Правила:
- сборка: pwsh -NoProfile -File .\build.ps1 (перед этим остановить процессы Kanban);
- интерфейс и документация на русском, стиль существующий, без фреймворков и CDN;
- данные только в папке приложения, без реестра и %APPDATA%, без прав администратора;
- синхронизация — снимком (kanban.json + files/), конфликты решает пользователь, пароль DPAPI;
- проверки: C:\Users\Bisik\AppData\Local\Temp\kanban-smoke.ps1 и kanban-sync-test.ps1
  (локальный WebDAV-сервер в webdav-mock), плюс реальный Mail.ru через kanban-mailru-test.ps1.

Сначала прочитай README и перечисленные файлы, затем предложи план правки, покажи diff и прогони тесты.
```
